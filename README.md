# Дипломный проект Яндекс.Практикум. UI e2e тестирование приложения Foodgram

## Описание проекта

Foodgram — это веб-приложение для публикации и поиска рецептов, в котором пользователи могут регистрироваться, входить в личный кабинет, создавать собственные рецепты и просматривать карточки блюд. Проект имитирует привычный пользовательский сценарий работы с сервисом: регистрация, авторизация, создание рецепта и проверка корректности отображения данных в интерфейсе.

В рамках дипломного проекта было выполнено UI e2e тестирование пользовательских сценариев в браузере. Основная цель — проверить, что ключевые элементы интерфейса работают корректно в реальных пользовательских действиях, а не только на уровне отдельных функций.

## Что тестировалось

В проекте автоматизировано несколько критичных пользовательских сценариев:

- регистрация нового пользователя;
- вход в систему под существующими учётными данными;
- открытие и работа с формой создания рецепта;
- заполнение полей нового рецепта;
- загрузка изображения рецепта;
- сохранение рецепта и проверка отображения карточки после публикации.

Проверяются не только отдельные элементы страницы, но и переходы между экранами, корректность URL, видимость элементов интерфейса и соответствие введённых данных тем, которые появляются после сохранения.

## Используемый стек и фреймворк

Для автоматизации выбраны:

- Python 3.12;
- Pytest — фреймворк для запуска тестов;
- Selenium WebDriver — автоматизация браузерных сценариев;
- Allure — сбор и визуализация отчётов по прогону тестов;
- Page Object Model (POM) — структурирование кода страниц и действий пользователя;
- Docker и Selenoid — запуск браузера в контейнере для UI-тестов.

## Подготовка и запуск проекта

### 1. Клонировать проект

```bash
git clone <адрес_репозитория>
cd Sprint_9
```

### 2. Создать виртуальное окружение и установить зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Запуск тестов локально

```bash
pytest -v --alluredir=allure-results tests/
```

Для просмотра отчёта Allure можно запустить:

```bash
allure serve allure-results
```

### 4. Запуск через Docker

В репозитории есть конфигурация `docker-compose.yml`, которая запускает Selenoid и контейнер с тестами:

```bash
docker compose up --build
```

Также можно запустить только контейнер с тестами после сборки:

```bash
docker compose up tests
```

### 5. Запуск тестов в контейнере

При сборке Dockerfile выполняется команда:

```bash
pytest -v --alluredir=allure-results tests/
```

Это позволяет сразу запускать UI e2e сценарии в изолированной среде и сохранять результаты в папку `allure-results`.

## Итог

Проект демонстрирует практическое применение автоматизации UI-тестирования в веб-приложении Foodgram на реальных пользовательских сценариях. Основной акцент сделан на проверке корректности работы интерфейса и бизнес-процессов через браузер, что соответствует задачам современной e2e автоматизации в QA.
